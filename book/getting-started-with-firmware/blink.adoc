=== LED blink

The code structure is the same across boards, but the LED connection is not.
The correct pin matters.
A call such as `gpio_put(25, 1)` may work on one board and fail on another, because the onboard LED is not always connected directly to the main microcontroller GPIO.
On the Pico 2 W, for example, the LED is routed through the wireless chip instead of the RP2350 GPIO pins.

For that reason, the examples in this section keep the same structure while adapting the pin selection for each board.

// * PICO_DEFAULT_LED_PIN
// * CYW43_WL_GPIO_LED_PIN
// * PICO_DEFAULT_WS2812_PIN

For this example you need the following files:

* `blink_simple.c` - C source code
* `CMakeLists.txt` - Configuration file used by the CMake meta-build system
* `.microCI.yml` - Pipeline

Once you have these three files in a folder just execute:

[,shell]
----
microCI | bash
----

.File formats created during the build.
[cols="2,3,12",options="header"]
|===
|Extension|Name|Description
|`.bin`|Binary|The raw, unstructured machine code. It is simply a stream of bytes that end up in the microcontroller's flash memory.
|`.dis`|Disassembly|A text file containing the human-readable assembly language instructions generated from your C/C++ code.
|`.elf`|Executable and Linkable Format|The primary compiled output of the compiler (GCC). It contains machine code alongside extensive debugging symbols, memory layout information, and source-code references.
|`.elf.map`|Map File|A text report generated by the linker mapping out the memory addresses of every function, variable, and constant in your program.
|`.hex`|Intel HEX|A text-based representation of the binary data. It encodes binary bytes and memory addresses into readable hexadecimal ASCII text.
|`.uf2`|USB Flashing Format|A format created by Microsoft specifically for drag-and-drop microcontroller programming. It wraps the raw code into 512-byte blocks containing metadata and destination addresses.
|===

[TIP]
Use **uf2 (USB Flashing Format)** for your standard workflow.

==== BOOTSEL

BOOTSEL (Boot Select) mode is a special USB mass-storage mode used to program
or reset your Raspberry Pi Pico.

===== Entering BOOTSEL Mode

1. Unplug the Raspberry Pi Pico from the computer.
2. Press and hold the small, white BOOTSEL button.
3. Plug the micro-USB or USB-C cable into the Pico while keeping the button held down.
4. Release the button.
5. The Pico will now mount to your computer's file explorer as a removable storage drive called RPI-RP2.

[TIP]
When in BOOTSEL mode the Pico will appear as a USB drive.

==== Loading firmware

===== If already in BOOTSEL mode

[source,console]
----
$ picotool load -x build/blink_simple.uf2
----

===== If your code is actively running

Force a quick reset and flash with the `-f` flag.

[source,console]
----
$ picotool load -fx build/blink_simple.uf2
----

[TIP]
**microCI** uses least privilege principle.

[IMPORTANT]
To deploy on hardware requires more privileges than the normal user supports by default.

The new options in `.microCI.yml` file are:

* `run_as: root` - execute commands in this step as `root`.
* `privileged: true` - the container gains almost full access to the host's kernel, hardware, and underlying system tools.
* `volumes:` - To map a Linux host's entire USB bus (`/dev/bus/usb`) to a Docker container
* `only: load` - Steps with `only` are executed alone and outside of the default pipeline
